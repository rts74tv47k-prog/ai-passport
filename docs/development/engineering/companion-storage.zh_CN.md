# 伴侣知识库存储

伴侣应用把人设、分类和已确认的文字记录放在 `storage` 分区。该分区是 IDF
wear levelling 之上的 FAT。不保存录音，只在用户确认后写入 UTF-8 转写文本。
日志可以包含 id、字节长度和错误码，不得包含人设正文、分类名或记录正文。

## 分区

| 分区 | 类型/子类型 | 偏移 | 大小 | 用途 |
| --- | --- | ---: | ---: | --- |
| `factory` | app/factory | `0x10000` | `0x400000`（4 MiB） | 应用镜像 |
| `storage` | data/fat | `0x410000` | `0x3F0000`（约 3.9 MiB） | 知识库 |

`storage` 不是预置镜像。首次成功挂载时，如果里面还不是 FAT，就会格式化。
普通应用烧录停在 `factory` 内，不会擦除 `storage`。`idf.py erase-flash` 会擦除它。
挂载使用 `esp_vfs_fat_spiflash_mount_rw_wl()`，挂载点 `/store`，并打开
`format_if_mount_failed`。文件系统无法挂载时会走格式化恢复，其中也包括旧的、
曾经覆盖到这个偏移的大 factory 镜像留下的数据。

## 容量和内存

记录文件上限 3 MiB，给 FAT 和磨损均衡留出开销。几百字节的短转写大约可以放
3000 条。删除只在原地位做标记。追加会超过上限、但存活数据仍然放得下时，
重写文件并丢掉已标记记录。本模块单次分配不超过 8 KiB。

## 文件

文件名使用 8.3，因此不需要长文件名。多字节文本只出现在文件内容里，不出现在文件名里。

| 文件 | 内容 |
| --- | --- |
| `PERSONA.TXT` | 单份人设 |
| `CATEG.DAT` | 32 个固定分类槽 |
| `RECORDS.DAT` | 只追加的记录日志 |
| `META.DAT` | 下一条记录 id 的缓存 |

人设、分类和 id 缓存各有一个对应的 `.NEW` 临时文件，写完后替换正式文件。
打开时，如果临时文件完整，就用它替换旧文件。`REC.OK` 用来提交压缩后的记录文件：
只有提交记录的长度和 `RECORDS.NEW` 一致时才采纳它。没有提交标记的临时文件会被删掉，
原来的记录文件保留。

## 记录日志

每条记录是 24 字节小端头加上转写正文：

| 偏移 | 字段 |
| ---: | --- |
| 0 | 魔数 `REC1` |
| 4 | Id，从 1 起 |
| 8 | 分类 id |
| 12 | Unix 时间；时钟未设置时为 0 |
| 16 | 正文长度，1 到 8192 |
| 18 | 删除标记的第一份 |
| 19 | 删除标记的第二份 |
| 20 | 前缀和正文的 CRC-32，不覆盖删除标记 |

只有两个删除标记都是 `1` 时，记录才算删除。两次写入之间掉电，记录仍然可见，
可以再删一次。文件末尾写了一半的追加会在下次打开时截掉。长度仍然落在文件内、
但 CRC 失败的记录会被跳过，后面的记录保留。

## 导出文本

`companion_files_export_txt()` 写出带 BOM 的 UTF-8，换行用 LF：

```text
# Categories
- name

# Records
[YYYY-MM-DD HH:MM:SS] name
transcript

```

Unix 时间 0 显示为 `[unknown]`。BOM 让 Windows 记事本和微信按 UTF-8 打开，
而不会把正文认错编码。分类名不允许控制字符，因此每个名字都留在同一行。
